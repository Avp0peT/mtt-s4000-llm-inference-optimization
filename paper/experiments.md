## 0. 研究问题（收敛后）

> **在 MTT S4000 单卡推理环境中，有限标定数据与执行状态描述如何影响成本预测可靠性；
> 改善这些问题后，能否减少错误调度并提高满足 SLO 的有效吞吐？**

**范围限定（写在前头，避免结论被读大）**：
* **单卡**、**单一模型**（Qwen2.5-7B-Instruct fp16）、**自建迭代级执行器**；
* 平台 = MTT S4000 / MUSA；**不**声称跨平台普适，**不**归因芯片固有机制；
* 成本预测 / deadline / 自适应 chunk **已有相近工作**（最接近的是 SLOWeave, arXiv:2609.07883）
  ⇒ **这些机制本身不作为算法贡献**；可贡献的是
  **"有限标定数据下如何获得可靠预测"** 与 **"预测失配怎样影响调度"**。

## 1. 五个阶段（每一段都写清"要看什么量、什么算失败"）

### 阶段一 · 平台与执行特征
| 项 | 内容 | 证据入口 |
| --- | --- | --- |
| 成本画像 | 快态平台（块 A）与服务协议（块 B）**分开采**；"不能只拟合快态最小值" | `COST_PROFILE_S4000.md`、`results/raw/_probe*` |
| 分层信号 | 为什么裸 TPOT 会被 prefill 污染；`decode_p90` 与 `tpot_p90` 的区别 | E9/E10/E12 登记行；`tests/test_monitor.py` |
| 执行形状普查 | 真实服务步的 `(batch, prefill_tok, kv_len)` 实际分布 | `scripts/check_model_coverage.py` |

### 阶段二 · **成本模型的失效分析**（本研究的核心增量）
| 问 | 怎么答 | 工具 |
| --- | --- | --- |
| 模型什么时候崩？ | 逐 batch 查**设计矩阵的秩**；报"五个数"（train n / holdout n / 训练最小秩 / 留出最小秩 / 低估 p95） | `scripts/costcalib_fit.py --split rank_guaranteed` + `diagnose_coverage` |
| 崩的原因是什么？ | **失效归因表**：训练秩不足 / 表达力不足 / 测试超范围 / 测量波动——**逐类给证据** | `NEXT_SESSION_TASKS.md` 的归因审计两节 |
| 当前特征够不够？ | 配对实验：保持模型输入不变、改变执行结构，看耗时是否稳定不同 | `scripts/diagnose_scheduling.py`（预测 vs 实际）、待补的 structure 探针 |

**已落地的两条结论（可直接引用）**：
1. 哈希划分对**训练覆盖**是抽签 ⇒ 同一模型 1-in-4 下 **1.77%**、1-in-2 下 **95.25%**；
   **真因是训练集秩不足**（`batch=8` 的训练集只剩纯 decode ⇒ 秩 2 < 参数 3）；
   **秩保证划分**把同等规模下的误差从 **95.26% 降到 11.77%**；
2. **v1 网格里秩 3 达不到**（无论怎么划分）⇒ 扩网格是**必要条件**；
   满秩后仍剩 **11.77%** ⇒ 那才是**模型自身的近似误差**（此时判据首次可信）。

### 阶段三 · 针对性改进
| 改进 | 依据 | 消融方式 |
| --- | --- | --- |
| **逐步按序列开销项** `overhead = a + b×batch`，**用真机 harness 的步**拟合 | 实测：纯 decode 步预测 100.2 ms vs 实际 130.4 ms、**每序列 ≈ +3.8 ms**（b8 时 +30 ms） | 只加这一项、其余不变 |
| **秩保证划分 + 覆盖诊断** | 见阶段二结论 1 | 与哈希划分对照 |
| （可能）**kb 加密的网格** | 见阶段二结论 2 | 2×2 解耦：{旧,新}网格 × {哈希,秩保证}划分 |

### 阶段四 · 调度影响（**证据链**：误差 → 错误决策 → 服务代价）
| 诊断 | 定义 | 工具 |
| --- | --- | --- |
| **D1 可行超时率** | 选中可行候选后**下一步**实际时长 > deadline 的比例 | `scripts/diagnose_scheduling.py` |
| **D2 保守等待** | `prefill 额度=0 且队列非空`的步占比 + `Σ队列·步` | 同上 |
| **D3 达标吞吐 / 达标率** | 照报（即使为 0） | `scripts/analyze_step14.py` |

### 阶段五 · 系统收益与适用边界
* 三个负载区：**正常服务 / 接近容量上限 / 过载** ⇒ **分别解释**；
  ⚠️ **全部方案 goodput 都为 0 的场景揭示的是过载边界，不能证明一般性能优势**；
* 冻结参数后，用**未参与调优的轨迹**与**独立运行**验证；以**独立运行**为统计单位算波动与置信区间；
* ⚠️ **「独立运行给置信区间」在本项目上被实测限定（P15，否定结论）**：
  `ramp` 是**开放环确定性**负载 ⇒ 同格 n=5 里 `static`/`cost` **逐位相同**（极差 0）、
  `threshold` 极差 0.001、`slo_weave` 出现过一次**控制轨迹分岔**（非噪声）。
  ⇒ **`ramp` 提供的是「4 个相同点 + 1 个离群点」，不是分布**：
  据此算置信区间由那 1 点单独决定，**无意义**。
  ⇒ 本阶段该条的**适用负载**须写成：**只有采样噪声敏感 / 开环非确定的负载格**才给 CI；
  **`ramp` 上改为「跨重复一致性检查」**（逐位相同/极差=0 本身就是一个可复核的结论）。
  ⚠️ 该限定是**负载的确定性**造成的，**不是样本量不足** ⇒ 加重复数**不能**解除；
  **不得**把"没给 CI"写成"待补 CI"。
* 第二个模型规模属增强项，等主结论建立后再做。

## 2. 每个实验必须**预先**写下的东西

在起 run **之前**填入 `EXPERIMENTS.md`：

1. **可证伪的预期**（含方向与量级）。「会变好」不是预期，因为它不可能被证伪；
2. **唯一变量**及其取值；
3. **不变项清单**：模型、精度、序列长度分布、并发、硬件、驱动、编译选项、
   **SLO**、**判据**（`signal_criterion`）、预热、计时口径；
4. **失败判据**（见第 4 节）。

事后补预期是本项目明令禁止的做法——那等同于把任意结果都解释成成功。

### 必须一起报的几组量

| 组 | 内容 | 为什么缺一不可 |
| --- | --- | --- |
| 尾延迟 | **TPOT 与 TPOT stall 分开报** | 只用 TPOT 会被大量快请求"平均"掉；实测同一 run 里 TPOT P99 = 74 ms 而 stall P50 = 968 ms，差一个数量级 |
| 预测层 | 留出误差的**五个数** + 模型**回退率** | 没有它们"误差"不可解释（哈希 1.77% vs 1-in-2 95.25% 就是同一模型） |
| 决策层 | **D1 / D2** | "误差下降"本身不是结论，要能说"错误决策减少了" |
| 服务层 | **D3 达标吞吐 / 达标率** | 最终收益；若为 0 也要照报并解释 |
| 结局层 | 失败 / 拒绝 / 未完成 率；账目自查误差 P99 | 否则"达标吞吐"可能建立在丢掉请求之上 |
| 溯源 | `git_commit` + `dirty` + `data_label` + **实际生效的判据** | 验收第 5 条；且"配置写了什么"不等于"实际用了什么" |

## 3. 负载 / cell 选择的理由

| cell | 定义 | 它代表什么真实场景 | 现状 |
| --- | --- | --- | --- |
| `fixed` | 固定长度、固定并发 | 稳态服务；**检查用** | 已跑（`S14B1`/`S14C1`） |
| `ramp` | low→high→recover 三段 | **非平稳负载**——与最接近方法（SLOWeave 评的是 chat/mixed/long/**bursty 到达分布**）的**真正差异点** | 部分跑（`S14B2` 6 次） |
| `lenmix` | 请求长度分布变化 | 长短混合下的取舍 | 未跑 |
| `slo_reach` | 更轻、**SLO 可达**的格 | 让"达标吞吐"这个头条量**有区分度** | **待登记**（需提前冻结设计并说明原因） |

⚠️ 已收掉的负载：`shared_prefix_4k`（前缀缓存专用）—— 前缀缓存已不在范围内。

## 4. 止损点（off-ramps，**从实际发生的事改写**）

* **成本模型在秩保证划分下仍 > 5%** ⇒ 说明"按 batch 分段 + 每段线性"这一族的**上限到此**
  ⇒ 改走**查表 + 保守回退**，并把**覆盖率**作为头部指标（而不是继续加密网格）；
* **留出 < 15 点** ⇒ 该格判据只能记 **「未判」**（不许用 3 个点的 p95 说事）；
* **加了"按序列开销"项而服务收益不变** ⇒ 如实报告"误差下降未转化为收益"，并解释原因；
* **任何实验若两次重复的稳健 CV > 10%** ⇒ 先修测量，不得进入对照比较；
* **某臂在某一格全面胜出**不构成本研究的必要条件 —— 本研究的结论形式是
  **"误差 → 错误决策 → 服务代价"的关系**，不是"某方法更好"。

## 5. 执行顺序（**实际走过的**，不是计划）

1. 环境指纹固化 + `--dry-run` 打通链路；
2. 分块预填充的尾延迟（P1S3/P1S3B/P1S3D）⇒ 结论 C1/C2；
3. 静态响应面 + **Best Static 冻结**（S10）⇒ 静态臂的对照值在此定稿；
4. 分层信号与判据（第 09 步）⇒ 冻结 `signal_criterion: decode_p90`；
5. 成本标定 v1 → **失效归因审计** → v3/v4（阶段二/三）；
6. 四臂对照（阶段四）—— 当前进度：`fixed` 已跑，`ramp`/`lenmix` 待补；
7. 第 15 步消融（只调 chunk / 只调 budget / 去掉误差裕量 / 换信号）；
8. 第 16 步写作。
