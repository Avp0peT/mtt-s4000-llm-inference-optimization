# Qwen2.5-7B × MTT S4000：八个可实施的优化方案

日期：2026-09-29。依据：本地 HEAD `16e82d2` 及当时未提交工作树、已入库环境与实验记录、下文列明的论文和官方资料。

本文是供逐会话实现的方案卡，不是已完成记录。没有实施以下改动、启动真机实验或改变既有实验裁定。方案编号为本文的 P1–P8，与已有 OPT-01 等会话编号分开；落实时将选定方案登记到现有任务清单，不把本文当成第二份进度账本。字段、脚本名凡写“建议”均为待实现接口。

## 1. 为什么选择这些方向

### 已核实的模型与平台

| 项目 | 当前依据 | 对优化选择的影响 |
|---|---|---|
| 模型 | Qwen2.5-7B-Instruct，revision `a09a35458c702b33eeacc393d103063234e8bc28`；项目执行精度 FP16 | 优先保持模型、权重与服务 SLO，单独改变执行机制 |
| 模型结构 | 28 层、hidden 3584、intermediate 18944、28 个 Q 头、4 个 KV 头、词表 152064 | 大词表输出层、GQA、小批量线性层都是具体切口 |
| GPU | 单卡 S4000，48 GB GDDR6，官方标称带宽 768 GB/s；张量 FP16/BF16 100 TFLOPS、INT8 200 TOPS | 容量足以支持多种缓存实验；低并发仍可能受访存/提交约束；INT8 值得探针，但不保证软件可用或 2 倍加速 |
| 当前栈 | 记录为 driver 2.7.0、MUSA 3.1.0、torch 2.2.0、torch_musa 1.3.0、Transformers 4.46.3 | 最新 CUDA/MUSA 项目的功能不能直接当成本环境已有能力 |
| 当前推理器 | 自研调度与 HF 逐步前向，已使用真实 KV cache | 不能把“开启 KV cache”当成新增优化；应减少重复打包、计算与提交 |

来源：[固定模型版本配置](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct/blob/a09a35458c702b33eeacc393d103063234e8bc28/config.json)、[S4000 官方规格](https://docs.mthreads.com/s4000/s4000-doc-online/product_specifications/)、[项目环境记录](C:/Users/13944/WorkBuddy/st/ascend-llm-inference-optimization/results/raw/_env/env.json)。硬件标称值不等于当前租用实例的持续性能。

由模型配置可计算：head_dim=3584/28=128，每 7 个 Q 头共享 1 个 KV 头；原始 FP16 KV 数据每 token 为 `2×28×4×128×2=57344 B=56 KiB`，单请求 8192 token 约 448 MiB，不包含 padding、分配器、工作区等额外开销。因此低并发阶段应先关注执行和搬运，不能仅因显存有余量就排除访存问题，也不必优先实现复杂 KV 压缩。

已有结果给出的限制：S6 的小 chunk 增加约 20.5% 步数，达标吞吐下降约 14%；OPT-01 未发现所分析 low 段进入慢态，且该条件下 b4 服务 TPOT 为 101.26 ms，高于 100 ms SLO。不要继续沿用“c4–c6 已可达”或“维持占空比必然有收益”的旧假设。

## 2. 共同实验约定

1. 一次实现一个机制，使用独立开关；先单项消融，再测组合。所有对照臂共用同一执行路径。
2. 保持同模型 revision、精度、请求内容、输出长度规则、SLO 和计时边界。执行路径变更后，更新所需成本标定与对照，不把旧模型预测值当成新路径的成本。
3. 正确性先于性能：复用已有多步 KV、变长 batch、chunked prefill 和资源生命周期验收；补与本次机制有关的反例。数值误差阈值在测量前确定，不能只看生成文本“像是正确”。
4. 性能先做少量代表形状的配对试验，再扩展。试验可先用 3 次独立运行筛选，正式结论按冻结协议增加重复。保留逐 run 原始精度，不把舍入后相等当作没有波动。
5. 同时记录端到端墙钟、TTFT、请求 TPOT、token 间隔尾延迟、达标吞吐、失败/拒绝率、峰值显存。算子计时改善不能替代全模型收益；诊断插桩与正式性能计时分开。
6. 原始结果保留不变；新实验使用新目录、可核验源码与配置指纹。基线/实验顺序交错，避免把热态或运行顺序当作优化效果。
7. 正式策略实验前先修当前两个问题：双预算不能因候选含 prefill 就忽略受阻 decode 的时间约束；闭环抖动的未来 release 必须真正等待，不能只后移 arrival 时间戳。think time 应由请求/客户端轮次确定，不能由策略相关 step 决定。
8. 若使用当前 SLOWeave 参考臂，先修重复应用 safety_margin，以及在有缺键的 lookup 定义域上使用连续二分的问题。修复后使用新实验条件，不悄悄改写历史对比。

统一交付物：实现开关与默认行为、针对性正确性证据、最小 A/B 配置、原始运行索引、自动生成的汇总、无收益/退化条件。不要在方案阶段承诺加速百分比。

## P1. 利用大词表结构，减少无用输出计算

**依据与位置。** 当前前向没有限制 logits 位置，随后仅取最后位置。[real_backend.py 前向入口](C:/Users/13944/WorkBuddy/st/ascend-llm-inference-optimization/benchmark/real_backend.py:1214)。固定版本 Qwen2 的 `num_logits_to_keep=0` 默认计算全部输入位置，传 1 可只做最后位置的输出投影。[Transformers 官方源码](https://github.com/huggingface/transformers/blob/v4.46.3/src/transformers/models/qwen2/modeling_qwen2.py)。这属于已有模型接口的有效使用，不单独作为算法创新。

**实现任务。**

1. 增加两个独立开关：末位置 logits、仅对 `need_token=True` 行采样；名称按项目配置风格确定。
2. 检查实际模型 forward 接口后传 `num_logits_to_keep=1`；不支持的模型明确保留原路径，禁止静默吞参数。
3. 中间 chunk 即使不输出 token，也正常更新全部 KV 和 past_len；仅跳过不用的采样及 D2H，正确恢复请求行索引。
4. 第一版保留同一模型 forward，不直接绕到 `model.model`；那会另引返回类型、结构和包装层差异。

**最小验证。** 先 greedy；覆盖 batch 1/4、prefill 128/512/2048、decode 1；`need_token` 全真、全假、混合。比较末位置 logits、逐层 KV、完整生成与峰值显存。随机采样另定义逐请求 RNG 契约，不能把减少 RNG 消耗后的逐 token 差异直接判成数值错误或无视它。

**验收与止损。** 两个开关各自 A/B，再测组合；decode 单 token 不应出现无法解释的巨大收益。减少的是输出层重复投影，不是整个 Transformer 的计算量，不预期端到端按 chunk 长度倍数加速。

## P2. 复用分配器、KV 与输入缓冲

**适配原因。** 单卡 48 GB 在现有低并发实验中提供了预分配空间；当前每步各层有 `pad/cat`，退役时还清理 allocator 缓存。[KV 打包](C:/Users/13944/WorkBuddy/st/ascend-llm-inference-optimization/benchmark/real_backend.py:1303)、[退役路径](C:/Users/13944/WorkBuddy/st/ascend-llm-inference-optimization/benchmark/real_backend.py:1358)。FlashInfer 的计划/执行分离与工作区复用可作设计参考，但不代表其 CUDA 实现可直接装到 MUSA。[FlashInfer](https://arxiv.org/html/2501.01005v2)

**实现任务。**

1. P2a：保留逐请求删除 slot，把常规 retire 中的 `empty_cache()` 改成可选的 run 边界行为；作为独立小改动验证。
2. P2b：仅为成员固定、历史等长的 decode 批建立持久 Cache；成员退出或补入时显式退回原路径。复用对象不等于消除了内部张量拼接，必须测分配与搬运。
3. P2c：复用 input_ids、position_ids、mask 的容量缓冲，更新有效区域；设备使用结束后才能覆盖。预分配容量纳入显存预算。
4. 第一阶段不重写通用 PagedAttention，不把“padding 比例小”当成“KV 重打包成本必然小”。

**最小验证。** batch 1/4/8、KV 512/2048/8192；先固定成员，再测混长、退出、补入、slot 重用。记录 allocated/reserved、分配重试、KV 搬运量、重排次数、请求边界 ITL 和完整步时。

**验收与止损。** reserved 增加不自动等于泄漏，但活跃内存不能无限增长；需验证长期周转与 OOM。收益若只发生在不会出现的固定成员微基准，不能外推动态服务。

**可复制会话指令：**

```text
按本文 P2 分阶段优化缓存生命周期。本会话先完成 P2a：逐请求仍释放 slot，
把清空 allocator 缓存从常规 retire 分离，保留独立开关并验证长期周转与内存峰值。
随后根据已测开销决定是否进入 P2b 的固定成员 decode Cache 复用；不要一次重写整个 KV 系统。
每一子项分别报告分配/搬运变化、完整步时、边界 ITL 与数值正确性。
```

## P3. Qwen 专用线性层融合与小批量形状选择

**论文依据。** FlashDecoding++ 指出 decode 的 GEMV/扁平 GEMM 与大 prefill GEMM 具有不同瓶颈，应根据形状选择执行方式。其 NVIDIA/AMD 结果不代表 S4000 的预期加速。[论文](https://arxiv.org/html/2311.01282v4)

**模型对应。** 对此 Qwen 配置，Q/K/V 输出维数为 3584/512/512，可合成一次 3584→4608 投影；gate/up 各 3584→18944，可合成一次 3584→37888 投影。融合减少调用及部分输入读取，不减少总权重或等价乘加总量。

**实现任务。**

1. 捕获真实模型中的线性层形状、dtype、stride 和调用频度，按 decode/prefill 区分。
2. 先使用现有 `F.linear` 与静态拼接权重实现 QKV 的 3→1、gate/up 的 2→1 调用；权重在装载时预处理，不能每个 token 都 concat。
3. QKV bias 必须一起按相同顺序拼接；切分输出时保留各自 head 形状，检查额外 contiguous/copy 是否抵消收益。gate/up 后仍按原语义执行 SiLU 和逐元素乘法。
4. 分开测试 QKV 融合、gate/up 融合，再测试组合。仅在库算子仍是明确热点时考虑 MUSA 自定义 kernel 或库算法选择。
5. 对小 batch 和 prefill 允许使用不同静态选择规则；规则在校准集上选择、冻结后用未参与选择的形状验收。

**最小验证。** decode 的 M=1/2/4/8 和 prefill 的 M=128/512；先真实输入的算子正确性，再逐层及全模型 logits、生成结果。比较独立层总耗时与融合层完整耗时，包含切分/布局处理。

**验收与止损。** 保留强基线：同栈原生 Linear/GEMM。只有某些形状改善时就限制启用范围，不通过人为削弱基线制造普遍收益。融合模块并非自动兼容量化、LoRA 或外部包装器。

**可复制会话指令：**

```text
按本文 P3 实现 Qwen2.5-7B 的线性投影融合候选。
先导出实际 QKV/gate/up 的形状与 bias；以现有 MUSA Linear 为基线，分别做 QKV 与 gate/up 融合。
权重只在装载时拼接，保持原权重可追溯；记录切分、布局转换、临时显存的完整成本。
用真实激活验证 M=1/2/4/8/128/512，完成全模型数值检查后再报告性能。
第一阶段不写自定义内核、不改量化和调度；给出各形状启用/禁用范围。
```

## P4. 保留 GQA 共享，减少 attention 的冗余访存

**模型与论文依据。** 28 个 Q 头共享 4 个 KV 头。若 attention 路径将 KV 显式扩展到 28 头，会失去部分 GQA 访存优势；必须先确认扩展是否实际物化。FlashAttention 的 IO 感知和 FlashInfer 的 KV 格式处理提供实现方向。[FlashAttention](https://arxiv.org/abs/2205.14135)、[FlashInfer](https://arxiv.org/abs/2501.01005)

**实现任务。**

1. 记录实际 attention 类与实际执行内核，检查 `repeat_kv`/expand/reshape 后的 storage、分配量与拷贝；不能仅按配置名推断。
2. 单独验证当前 MUSA 栈是否有可用的原生 GQA attention，接口是否支持本项目的因果 mask、不同 q_len/kv_len、FP16、左 padding 和缓存布局。
3. 若存在可用实现，写一个可关闭的 adapter；先做纯 decode，再做 chunked prefill。无可用内核则止于支持度报告，或另立内核任务，不静默回退 CPU。
4. 只设置 `enable_gqa` 之类选项不算完成；要用实际分配/执行证据证明没有物化复制，并核对是否退回普通 math 路径。

**最小验证。** batch 1/4；q_len 1/128，kv_len 512/2048/8192；长短缓存混合、因果 mask、最后几个 token 的位置偏移。比较 attention 输出、全模型 logits、KV 大小和端到端收益。

**验收与止损。** 避免 KV 头复制的 7 倍尺寸差不等于整体加速 7 倍。若当前已用有效 GQA，或 attention 占比很低，结束该路线；不能为了更快而近似 softmax 却继续声称数值等价。

**可复制会话指令：**

```text
按本文 P4 做 Qwen GQA attention 支持度与热点探针。
先确认当前实际 attention 后端及 repeat_kv 是否物化，再验证本机栈已有的原生 GQA 内核。
实现可关闭 adapter 的前提是 mask、位置、FP16、缓存语义全部支持且通过数值检查。
输出每形状的分配、attention 与完整模型耗时；没有适配实现就明确记录，不把 CUDA 支持当作 MUSA 支持。
```

## P5. 减少同步与按形状捕获 decode 图

**适配原因。** 当前逐组前向后有全设备同步，随后才采样并回传；固定 batch decode 每步重复大量相同提交。[当前路径](C:/Users/13944/WorkBuddy/st/ascend-llm-inference-optimization/benchmark/real_backend.py:1225)。图捕获可减少提交开销，但旧 MUSA 栈的可用性需要能力探针，不能将最新文档能力回填到旧环境。

**实现任务。**

1. P5a：诊断运行用设备事件分解搬运、forward、采样；正式运行保留 token 真正回到主机后的时间戳。
2. 验证同流 forward→采样→D2H，移除其中冗余的全设备同步。全部 `need_token=False` 的批没有 D2H 兜底，必须另有完成与计时契约。
3. P5b：仅在支持度与 P2 静态缓冲通过后，为小规模 batch/容量桶捕获纯 decode；动态 prefill 和不支持形状保留 eager。
4. 捕获要求地址、缓存布局稳定；position、有效长度与 mask 仍需正确更新。不能把不断增长的 KV 当成固定 shape 后直接重放。
5. 分别报告捕获时间、常驻显存、命中率、回退率、稳态延迟和摊销所需请求量。

**最小验证。** batch 1/2/4，多个 KV 长度、连续增长、桶切换、退出补入；eager 与 replay 使用相同完整生成任务。

**验收与止损。** CPU 提交变快而 token-ready 不变，不算部署收益；无法正确捕获或频繁回退时保留 P5a 的独立结论，不继续为图捕获重构所有路径。

**可复制会话指令：**

```text
按本文 P5 先完成计时和去冗余同步的独立实验，确保 token-ready 在真正完成后记录。
然后检测当前 MUSA 栈的图捕获能力，仅对已具备稳定缓冲的纯 decode 桶做原型。
覆盖 KV 增长、桶切换及 eager 回退，分别报告稳态收益与捕获/显存成本。
不得把无依赖的异步前向吞吐当成自回归生成性能。
```

## P6. 依据实际算子选择 W8A8 或 W4A16

**论文与硬件对应。** SmoothQuant 通过离线处理激活异常值支持 W8A8；AWQ 是低比特权重量化路线，W4A16 的加速依赖相应反量化/GEMM 实现，不能用 S4000 的 INT8 峰值推算其收益。[SmoothQuant](https://arxiv.org/abs/2211.10438)、[AWQ](https://arxiv.org/abs/2306.00978)

**实现任务。**

1. 先验证当前软件栈在一个真实 Qwen Linear 上是否执行真实 INT8 或融合低比特内核；量化权重存成 int8/int4 后每步完整还原 FP16，不等于获得加速。
2. W8A8 探针包含激活量化、缩放、GEMM、输出转换；W4A16 探针包含完整反量化成本。对照 FP16 原生库路径。
3. 以 M=1/2/4/8 和 M=128/512 判断适合 decode 还是 prefill；只将有收益且质量可控的线性层纳入模型替换。
4. 从少数层到完整模型分阶段推进；保留 FP16 回退，记录真实保留的高精度层和额外 scale/metadata 显存。
5. 校准文本与质量测试文本分离。量化验收使用固定任务指标/困惑度及允许下降范围，逐 token 一致率仅作诊断，不作为唯一质量标准。

**验收与止损。** 先冻结可接受质量损失与最小实际收益。无快速原生内核、收益被转换吞没或质量越界，则不升级为整模型量化任务。FP16/BF16→INT8 的标称算力比例不是端到端收益预测。

**可复制会话指令：**

```text
按本文 P6 做量化可行性筛选，先验证当前 S4000 软件栈真实可调用的低精度 Linear。
比较 FP16、可用 W8A8 与可用 W4A16 的完整成本，包含转换、scale、反量化和临时显存。
只对实测可用且有收益的分支制定完整模型替换与独立质量评估计划。
不要只下载量化权重就宣称完成加速，也不要为探索覆盖当前可复现实验环境。
```

## P7. 执行形状与分块总成本感知调度

**研究切口。** S6 表明小 chunk 可增加总步数并降低 goodput；因此应同时建模一步成本和完成剩余 prefill 的成本。Sarathi-Serve 支持分块与实际混合批处理共同设计；SLOWeave 已有成本预测、deadline 与最大安全 chunk，不能将这些已有要素单独声称为本项目创新。[Sarathi-Serve](https://arxiv.org/abs/2403.02310)、[SLOWeave](https://arxiv.org/abs/2609.07883)

**实现任务。**

1. 先为候选计划导出真正会执行的 forward 分组、每组 batch/q_len/kv_len、搬运与分配需求，而非仅使用总 prefill token 数。
2. 显式导出包含新测点的新成本模型并检验部署路径；v8 探针有 192 数据，不等于当前 model_v7 已包含相应键。分别报告真实候选覆盖率、命中误差、未命中与超预算比例。
3. 保留实际可执行的离散候选；模型缺键不能靠连续二分假定单调性。不假定 batch 或总步时必然单调。
4. 若采用逐 token deadline 护栏，按全部受阻 decode 的剩余时间计算，而非只看本步是否含 prefill。该护栏与请求平均 TPOT 不是同一指标，论文应明确映射，不能声称硬保证。
5. 对 TTFT 考虑已排队时间与完成剩余 prompt 的预计时间；不能将一个 chunk 的预算当成整个请求的 TTFT 预算。
6. 在安全候选中显式考虑剩余 chunk 次数和重复执行代价，记录选择理由、实际动作与成本。保留静态/no-op 回退；选择规则在校准负载上冻结。
7. 在线残差校准可作独立增强：只使用已经完成的历史观测，区分不同执行形状，限定更新幅度并记录全部校准开销；未知形状不能仅因一个缩放系数就变成可信预测。

**最小实验。** 固定优化后引擎，对照最佳静态、现有成本策略、仅修正形状模型、再加入分块总成本规则。S6、ramp、长度混合分别测试；按独立运行统计，不挑选有利负载。在线校准最后单独消融。

**验收与止损。** 覆盖和误差达标仍不等于系统收益；必须在相同 SLO 下比较 goodput、TTFT、token 间隔、额外计算及控制开销。无稳定收益时保留负结果，不继续调整负载直到通过。

**可复制会话指令：**

```text
按本文 P7 设计执行形状与分块总成本感知策略，先修复当前双预算的 decode 保护语义。
核实部署模型真实覆盖，把 TTFT 剩余时间与受阻 decode 的时间约束分开表达并同时检查。
先实现逐候选分组成本及可审计选择记录，完成反例测试；再加入剩余分块代价的独立开关。
对照最佳静态与现有策略，保留 S6 防退化场景。在线校准独立实施，不与主体策略一并变化。
交付可证伪假设、冻结规则、小批试验矩阵和停止条件，不预写正收益。
```

## P8. 低并发推测解码，优先不引入第二模型

**论文与平台对应。** 推测解码通过一次目标模型验证多个候选 token，减少串行目标模型调用；适合先在低并发、较长输出上试验。单卡有显存不代表额外计算免费，草稿成本和拒绝回滚可能抵消收益。[Speculative Decoding](https://arxiv.org/abs/2211.17192)

**实现任务。**

1. 为保持当前单目标模型研究范围，先试 prompt/history 的确定性 n-gram 候选；这是借用批量验证机制的提案，不是上述论文声称已验证本项目 n-gram 实现。
2. 第一阶段限定 greedy，候选长度 2/4；目标模型一次返回验证所需的所有位置 logits。P1 的末位置开关在验证路径上必须按需切换，不能全局固定为 1。
3. 目标模型逐位置验证，接受公共前缀；遇到拒绝时输出目标模型选择并正确裁剪/回滚 KV。EOS、长度上限、全接受/首个拒绝/部分接受均需覆盖。
4. 报告每次接受 token 数、目标验证成本、候选生成成本、KV 回滚成本以及总墙钟；只报接受率不够。
5. 若以后引入小草稿模型，另立部署分支并核验 tokenizer/vocabulary/token-id 映射，不能凭同属 Qwen 就认为可直接混用。随机采样需要完整的接受/拒绝校正算法，不能用 greedy 的处理冒充分布等价。

**最小实验。** 并发 1/2，输出 128/512；包含重复性高与低的真实文本任务。greedy 输出应与原目标模型一致；同时记录 token 释放的时间序列，防止只改善平均吞吐却增加尾部间隔。

**验收与止损。** 用“总耗时/实际生成 token”与原生解码对比，包含全部开销。低接受率或高并发下退化应触发关闭；普通文本无收益也属于有效结论，不只展示复制型任务。

**可复制会话指令：**

```text
按本文 P8 做不增加第二模型的 greedy 推测解码原型：先用确定性 n-gram 候选，长度2/4。
实现目标模型多位置验证、接受前缀和 KV 回滚；验证路径显式请求所需 logits，避免与 P1 冲突。
先用正确性反例覆盖全接受、首个拒绝、部分接受、EOS及长度上限，再做并发1/2的端到端对照。
同时报告高重复与普通文本的收益/退化、接受数、全部额外成本及 token 时间间隔。
```

## 4. 基线与论文收束

成熟引擎对照应尽早做可行性检查，但它不算新增算法。使用官方 S4000 支持的具体 vLLM-MUSA 镜像，核验实际驱动/SDK/模型/算子兼容性；与自研引擎使用相同外部计时边界与工作负载。官方推荐环境与当前旧栈不同，不能直接照最新分支安装。[官方 S4000 环境说明](https://docs.mthreads.com/vllm-musa/vllm-musa-doc-online/S4000/environment_setup/)

建议论文首先选择“一个执行优化 + 一个调度机制”，形成以下四组：

| 执行路径 | 策略 | 所回答的问题 |
|---|---|---|
| 原执行路径 | 冻结的最佳静态 | 原始参照 |
| 优化执行路径 | 同一静态 | 执行优化贡献 |
| 原执行路径 | 新策略 | 调度贡献 |
| 优化执行路径 | 新策略 | 组合收益与交互 |

P1/P2 的工程改进适合支撑可用系统；P3/P4/P7 有更深入的研究空间，但必须经过与强基线的比较和相关工作区分。P6/P8 属于有条件扩展，无需全部实现才能完成论文。

建议第一会话执行 P1；随后完成 P2a 与 P3 的最小筛选。每个方案收尾只做三选一：保留并进入更大验证、限定适用范围、记录无收益后停止。把资源集中在已经通过正确性且有端到端信号的方案上。
